# M1 接口、通信与风险说明

## 一、数据接口说明

### 1. OpenSky外部数据接口
- **格式**: JSON数组，每个元素包含id和vector字段
- **vector字段**: 按索引位置定义（0=icao24, 1=callsign, 5=lon, 6=lat等）
- **风险**: 字段索引依赖位置而非名称，索引偏移会导致字段错位
- **风险**: time_position和last_contact可能为null，需回退处理

### 2. TeachingLink 41字节帧接口
- **格式**: 固定41字节，大端字节序，一帧一条消息
- **封装**: 不使用IEEE浮点数，全部使用无符号整数+比例因子+偏置
- **风险**: 字节序错误（大端vs小端）会导致所有数值错误
- **风险**: target_id的24位编码不能用4字节struct直接写入

### 3. CSV/SQLite存储接口
- **CSV**: UTF-8 with BOM编码，以便Excel正确读取中文
- **SQLite**: None映射为NULL，布尔值映射为0/1
- **风险**: CSV编码错误导致中文列名乱码

## 二、通信与传输说明

### 传输模型
- 本实验使用文件模拟传输，非真实网络通信
- 每帧41字节独立写入二进制文件，无帧分隔符
- 接收端按41字节固定长度切分

### TeachingLink协议性质
- **重要**: TeachingLink是学校自定义教学协议
- **不对应** ASTERIX、ADS-B/Mode-S、Link 16或任何行业标准
- 仅用于教学演示，不用于真实装备接入

## 三、校验机制

### 1. Checksum校验和
- **算法**: 前39字节之和模65536
- **位置**: 帧偏移39-40
- **风险**: 简单校验和不能检测字节重排错误

### 2. 保留位检查
- latitude_code/longitude_code最高2位必须为0
- status_flags的bit3-bit7必须为0
- validity_flags的bit7必须为0
- **风险**: 保留位非零可能表示数据损坏或编码错误

### 3. 标志一致性检查
- 有效位为0时占位码必须为0
- 有效位为0但占位非零 → FLAG_VALUE_INCONSISTENCY
- **风险**: 标志与数据不一致可能导致误解释

## 四、主要工程风险

### 高风险
1. **字段缺失/空值混淆**: time_position为null时需回退last_contact；两者均空不能生成帧
2. **字节序错误**: 网络字节序（大端）与主机字节序不一致导致所有数值错误
3. **量化误差累积**: 定点编码后只能恢复到最近量化值，roundtrip误差不超过1个量化单位
4. **target_id前导0丢失**: 112233不能存储为0x112233的数值后直接格式化

### 中风险
5. **保留位异常**: 编码时未正确清零或接收端未检查
6. **callsign超长/非ASCII**: 超过8字符或含非ASCII字符应报错
7. **航向越界**: heading=360度应判定为越界（范围[0,360)）
8. **高度来源混淆**: baro和geo不能混用，需正确设置alt_type

### 低风险
9. **message_seq回绕**: 65535后按模65536回绕
10. **SQLite写入/读取不一致**: NULL值映射和回读验证

## 五、CSV和SQLite的角色

- **CSV**: 主要持久化格式，人类可读，便于检查和提交
- **SQLite**: 选做持久化，支持SQL查询和结构化检索
- **两者互补**: CSV用于提交和审查，SQLite用于查询验证
